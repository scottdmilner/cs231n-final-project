Based on the search results, I can now provide a comprehensive answer about running scripts after building but before packaging in scikit-build-core.

Scikit-build-core doesn't have a built-in "post-build hook" feature in the traditional sense, but there are several effective approaches to run scripts after building but before the wheel is packaged.

## Recommended Approaches

### 1. Use CMake Install Commands

The most straightforward approach is to use CMake's install phase to run custom commands. Since scikit-build-core executes `cmake --install` before packaging the wheel, you can add custom commands that run during installation\ue202turn3search4:

```cmake
# In your CMakeLists.txt
install(CODE "
    execute_process(
        COMMAND ${Python_EXECUTABLE} ${CMAKE_SOURCE_DIR}/scripts/post_build.py
        WORKING_DIRECTORY ${CMAKE_INSTALL_PREFIX}
    )
")
```

This executes your script during the install phase, which happens after building but before the wheel is packaged.

### 2. Install to Special Wheel Directories

Scikit-build-core provides environment variables for different wheel directories that you can use in your CMake configuration\ue200\ue202turn3search4\ue202turn1search5\ue201:

- `${SKBUILD_SCRIPTS_DIR}` - for executables/scripts
- `${SKBUILD_DATA_DIR}` - for data files  
- `${SKBUILD_HEADERS_DIR}` - for header files
- `${SKBUILD_PLATLIB_DIR}` - for platform-specific files

To use these experimental features, enable them in `pyproject.toml`:

```toml
[tool.scikit-build]
experimental = true

[tool.scikit-build.wheel]
install-dir = "/scripts"  # or other directories
```

### 3. CMake Custom Commands with POST_BUILD

You can add custom commands to run after specific build targets:

```cmake
add_custom_command(
    TARGET your_target POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E echo "Running post-build script..."
    COMMAND ${Python_EXECUTABLE} ${CMAKE_SOURCE_DIR}/scripts/process_outputs.py
    WORKING_DIRECTORY ${CMAKE_CURRENT_BINARY_DIR}
)
```

### 4. CMake Install Script

For more complex operations, create a separate CMake script and execute it during installation:

```cmake
# create_additional_files.cmake
file(WRITE "${CMAKE_INSTALL_PREFIX}/mypackage/generated.txt" "Generated content")

# In CMakeLists.txt
install(SCRIPT ${CMAKE_SOURCE_DIR}/create_additional_files.cmake)
```

## Configuration Example

Here's a complete example in `pyproject.toml`:

```toml
[build-system]
requires = ["scikit-build-core"]
build-backend = "scikit_build_core.build"

[project]
name = "mypackage"
version = "0.1.0"

[tool.scikit-build]
experimental = true
cmake.minimum-version = "3.15"
```

And in your `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.15)
project(mypackage)

# Your normal build steps
add_library(myextension MODULE src/extension.cpp)

# Install the built extension
install(TARGETS myextension DESTINATION mypackage)

# Run custom script after installation
install(CODE "
    message(STATUS \"Running post-build script...\")
    execute_process(
        COMMAND \${Python_EXECUTABLE} \${CMAKE_SOURCE_DIR}/scripts/post_process.py
        RESULT_VARIABLE script_result
    )
    if(NOT script_result EQUAL 0)
        message(FATAL_ERROR \"Post-build script failed\")
    endif()
")
```

## Important Notes

- The install phase runs **after** CMake builds everything but **before** the wheel is created\ue202turn0search7
- Scripts run during `install(CODE ...)` have access to CMake variables like `CMAKE_INSTALL_PREFIX`
- For modifying wheel contents, working within CMake's install mechanism is the supported approach
- There's no Python-level hook system in scikit-build-core like setuptools' cmdclass\ue202turn2search2

This approach integrates naturally with scikit-build-core's build process and ensures your custom operations happen at the right time in the build-install-package pipeline.
