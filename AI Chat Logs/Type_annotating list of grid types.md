You cannot directly use a list variable as a type annotation in Python. Instead, you need to explicitly create a `Union` type or type alias from those types. Here are the recommended approaches:

## Use Union Type Directly

The most straightforward approach is to explicitly define a `Union` type with all the types:

```python
from typing import Union

def my_function() -> Union[FloatGrid, BoolGrid, Vec3SGrid]:
    ...
```

Or using Python 3.10+ syntax:

```python
def my_function() -> FloatGrid | BoolGrid | Vec3SGrid:
    ...
```

## Create a Type Alias

For reusability, define a type alias in your `.pyi` file:\ue200\ue202turn1search1\ue202turn1search4\ue201

```python
from typing import Union

GridType = Union[FloatGrid, BoolGrid, Vec3SGrid]

def my_function() -> GridType:
    ...
```

Or with Python 3.10+:

```python
GridType = FloatGrid | BoolGrid | Vec3SGrid

def my_function() -> GridType:
    ...
```

## Why the List Doesn't Work

The `GridTypes: list = [FloatGrid, BoolGrid, Vec3SGrid]` definition creates a runtime list object, not a type annotation. Type checkers like mypy cannot extract type information from runtime list values. Type annotations must be static expressions that the type checker can analyze without executing the code.\ue200\ue202turn1search0\ue202turn1search1\ue201

**Recommendation:** Replace your `GridTypes` list with a `Union` type alias as shown above. This provides proper type checking while maintaining a single source of truth for which grid types are valid.
